# Файл пояснення до практичної роботи: Модульне тестування (Unit Testing)

### 1. Який клас і які методи ви перевіряєте модульними тестами?
Модульними тестами перевіряється клас `BankAccount`, який відповідає за управління банківським рахунком. Тестуванню підлягають такі методи:
- `Deposit(decimal amount)` — метод поповнення балансу.
- `Withdraw(decimal amount)` — метод зняття коштів з рахунку.

### 2. Чим відрізняються вхідні дані, очікуваний результат і фактичний результат тесту?
- **Вхідні дані:** Параметри, що передаються в методи під час виклику (наприклад, сума поповнення `50m`, сума зняття `40m`, або помилкові дані на кшталт `-5m` та `150m`).
- **Очікуваний результат:** Стан системи або значення, яке ми заздалегідь прогнозуємо отримати згідно з бізнес-логікою (наприклад, новий баланс `150m` або генерація винятку `ArgumentException` / `InvalidOperationException` при збереженні початкового балансу `100m`).
- **Фактичний результат:** Реальний стан об'єкта або виняток, який повернув код після виконання методу під час тестування. Тест вважається успішним (`PASS`), якщо очікуваний і фактичний результати повністю збігаються.

### 3. Який граничний або помилковий випадок ви перевірили та чому?
Перевірено два критичних помилкових випадки:
1. **Зняття суми, що перевищує поточний баланс** (`Withdraw(150m)` при балансі `100m`). Це важливий граничний випадок, який захищає рахунок від мінусового балансу. Тест підтверджує генерування винятку `InvalidOperationException` і збереження незмінного балансу (`100m`).
2. **Поповнення від'ємною або нульовою сумою** (`Deposit(-5m)`). Перевіряє захист від некоректного вводу даних (виняток `ArgumentException` із гарантією збереження попереднього балансу).

### 4. Як запустити всі ваші тести повторно і визначити, чи пройшли вони?
Для повторного запуску тестів у середовищі Visual Studio необхідно:
1. Відкрити головне меню **Test** -> **Run All Tests** (або натиснути комбінацію клавіш `Ctrl + R, A`).
2. Відкрити вікно **Test Explorer** (Test -> Test Explorer), де відобразиться список усіх чотирьох тестових методів.
3. Успішно пройдені тести позначені зеленими галочками (`PASS`), що свідчить про повну відповідність фактичної поведінки коду очікуваній.
