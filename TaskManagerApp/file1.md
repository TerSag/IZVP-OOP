# Відповіді на контрольні запитання (Практична робота №16)

### 1. Які два компоненти Avalonia UI ви створили та яку роль вони виконують?
**Відповідь:** Створено два власні компоненти на основі `UserControl`:
- **`TaskActionButton`** — універсальний повторно використовуваний компонент кнопки дії, який налаштовується через властивості (`ButtonText`, `IsDanger`) під різні сценарії (зміна статусу або видалення) та генерує подію `ActionClicked`.
- **`TaskCard`** — картка окремого завдання, яка інкапсулює відображення назви, поточного статусу та містить два екземпляри `TaskActionButton` для керування конкретним завданням.

### 2. Які дані передаються до компонентів через властивості або прив’язку?
**Відповідь:** Через механізм `StyledProperty` та XAML-прив'язку (`{Binding}`) у `TaskCard` передаються назва завдання (`TaskTitle`), текстовий статус (`StatusText`), стан виконання (`IsTaskCompleted`) та підпис кнопки зміни стану (`CompleteButtonLabel`). У `TaskActionButton` передаються текст кнопки (`ButtonText`) і прапорець небезпечної дії (`IsDanger`), який визначає колірне оформлення.

### 3. Як дія з компонента змінює стан завдання в основному застосунку?
**Відповідь:** Під час натискання внутрішньої кнопки `TaskActionButton` викликає подію `ActionClicked`. Компонент `TaskCard` перехоплює її, визначає прив'язаний об'єкт `TaskItem` із власного `DataContext` та генерує власну подію (`ToggleCompleteRequested` або `DeleteRequested`), передаючи цей `TaskItem` у `MainWindow`. Головне вікно обробляє подію, змінює властивість `IsCompleted` або видаляє елемент із `ObservableCollection<TaskItem>`, після чого інтерфейс і лічильник автоматично оновлюються.

### 4. Де в коді видно повторне використання компонентів без дублювання?
**Відповідь:**
1. У розмітці `TaskCard.axaml` компонент `TaskActionButton` використовується двічі поспіль для різних дій (`CompleteActionBtn` та `DeleteActionBtn`) без дублювання XAML-опису самої кнопки та її стилів.
2. У `MainWindow.axaml` у шаблоні `DataTemplate` списку `TasksListBox` оголошено лише один екземпляр `<local:TaskCard ... />`, який динамічно створюється для кожного доданого завдання (двох і більше) без копіювання розмітки карток.
